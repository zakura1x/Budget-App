Table shapes (see ARCHITECTURE.md §4):
  A = operational. Ordinary indexed columns, no financial data.
  B = data. id + user_id + key_version plaintext; everything else is one
      encrypted VARBINARY(MAX) payload.

Three rules this tree encodes:

  1. app/core/crypto/ and app/db/repositories/ are the ONLY places that see a
     key or a ciphertext. Services receive decrypted domain objects. A service
     author should never have to remember to encrypt anything.

  2. app/web/static/dist/ IS COMMITTED. It is Vite output built on your PC.
     The server has no Node and no npm, permanently. Deploy = git pull +
     restart. .gitignore excludes frontend/node_modules/ but explicitly
     keeps dist/.

  3. There is ONE key to the data: .env (BUDGET_MASTER_KEY). The 12-word
     recovery phrase was removed on 2026-09-14 (its code and columns went the same day).
     The server owner keeps an OFFLINE COPY of the whole .env - two places,
     off the server, never beside the backups, refreshed whenever a key
     changes. Lose .env and every copy and every row above is permanently
     unreadable by anyone, for every user.

  4. Every transaction payload carries a `splits` array, even single-
     category ones. category_id therefore lives one level deeper inside
     the ciphertext, and category delete, verify_integrity.py and every
     stats aggregation must walk it. No FK can catch a mistake here.
